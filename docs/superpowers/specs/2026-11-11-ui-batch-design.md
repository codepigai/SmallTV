# 操作改进批次设计（2026-11-11）

**来源**：v1.1 真机验收通过后的 6 条操作改进反馈，逐条与用户对齐于同日 brainstorm。
**范围裁决**：原第 4 项「回看功能」经侦察后**用户裁决砍掉**——服务器 381 频道中 287 标 `catchup="none"`（含全部真电视直播），94 候选里 16 路 B站 relay 实测忽略 `playbackbegin/playbackend` 参数、57 路央视景观 proxy 上游全坏（且为 24h 慢直播）、18 路外部源是公网直播流不走 iPTV 回看协议；当前订阅无任何可用回看源，不做。

本批次共 5 项：①延迟毫秒绿色 ②首页画廊显示模式 ③播放页键位重构 ④订阅管理界面改版 ⑤设置页（新增）。

## 全局约束

- minSdk 23 / target 34，Kotlin 单模块，media3 1.2.1，传统 Views（无 Compose），**不新增依赖**。
- 版本号不 bump（用户铁律：明确说升版才升）。
- TDD：纯逻辑（设置存取、派生计算）先写 JVM 失败测试；纯 XML/视觉部分走真机验收。
- API 28+ 方法（如 `Handler.hasCallbacks`）不可用。

## ① 延迟毫秒数绿色

首页频道行「网络~xxms」改**绿色 `#4CAF50`**；画廊卡片上的 xxms 同。

- **只绿毫秒段**：`chNow` 是复用 TextView，同时显示「正在播节目名　·　网络~xxms」（HomeActivity L266-273），且 `item_channel.xml` 还被抽屉（写分组名）与收藏行（写「已收藏」）复用——**不得**改 XML 整行颜色（会全传染）。在 ChannelAdapter 绑定时用 `SpannableString` 只给「网络~xxms」片段上绿色 ForegroundColorSpan；节目名、抽屉分组名、「已收藏」一律保持原色。画廊卡片本来就只有 xxms，直接绿。
- 播放页信息面板的 rtt 行不在本项范围（它不在「频道上」）。

## ② 首页频道列表 / 画廊双模式

- **画廊卡片**（新 `item_channel_grid.xml`）：上部大图像区＝台标 logo 放大居中（Glide；无 logo 用灰底占位图标），下部频道名一行 + 绿色「网络~xxms」。
- **规格**：一行 N 路、行数随屏高（约 3 行）；N 在设置页调（2–5，默认 3）。用 `GridLayoutManager(spanCount=N)`。
- **行为与列表一致**：聚焦即测速（复用 `probeChannel`）、确认=播放、长按=节目单。
- **作用范围（裁决修正）**：仅「全部」tab 的频道列表切宫格；**收藏 tab 保持列表不变**（收藏行现无测速、无长按节目单，本批次不为收藏新增行为，避免发明「收藏卡要不要 xxms/tvgId」的连带问题）；分组列不动。
- **模式记忆**：持久化（见⑤），重启 App 保持。

## ③ 播放页键位重构（PlaybackActivity）

- **删除底部控制条**（上一台/下一台/收藏/节目单/退出五按钮整条）；连带 `setControls`/`controlsShown`/`hideControls` 与 `ctrl*` 代码清除。**收藏功能移除**（用户确认：只在首页收藏）；**左键无功能**（用户确认）。
- 新键位：
  - **上/下** ＝ 换台（原 LEFT/RIGHT 的 `step(-1)/step(1)` 语义平移到 UP/DOWN）。
  - **确认（CENTER/ENTER）** ＝ 呼出节目单 `EpgPanel`（本就右侧滑出 460dp，触发键从"控制条里的节目单按钮"改直绑）。
  - **右键** ＝ 呼出频道列表：复用多屏的 `ChannelDrawer`（构造签名与 EpgPanel 相同 `(root, repo, scope)`）；`show(currentUrl, onPick)`，选中→ `restartWith(name,url,tvgId)` 并收抽屉。
  - **〔2026-11-12 真机验收改判③〕** 右键改为呼出**收藏夹列表**：`ChannelDrawer.show` 增 `favOnly: Boolean = false` 模式——频道列恒为全局收藏行（`favoritesToRows`），分组列只留「收藏」，标题「收藏夹」，空收藏给引导文案；选中→ `restartWith` 并收抽屉。收藏本就跨订阅（首页播收藏亦不依赖当前订阅），与裁决6「换台恒在当前订阅」不冲突。多屏默认参数不受影响。
  - **订阅 chips 隐藏（裁决）**：抽屉现有「≥2 订阅显示切换 chips」是为多屏同屏设计的；播放页换台语义始终是**当前订阅**（`step()` 也只在当前订阅内定位），跨订阅选台会让 UP/DOWN 换台断链（streamUrl 定位失败跳首尾）。给 `ChannelDrawer.show` 加 `showSubChips: Boolean = true` 参数，播放页传 false。多屏行为不变。
  - **MENU** ＝ 信息面板（保持现状）。
  - **BACK** 分层：频道列表开→关它；否则节目单开→关它；否则信息面板开→关它；否则退出播放页。
- **面板互斥**：呼出其一自动收其二。
- **键路由细则（我的裁决）**：面板打开时焦点在面板行内，DPAD 由列表消费（导航/选中），UP/DOWN 换台只在无面板打开时生效——依赖 Android 焦点分发天然实现，验收点。
- **〔2026-11-12 真机验收修订②〕** UP/DOWN 的拦截条件修正为**焦点确在面板内**（`hasFocusInside`）：面板开着但焦点未落入（EPG 无数据、首次打开落焦失败）时换台键不得做死——放行换台，换台路径 `restartWith` 会同步刷新开着的面板。终审 I1 的边界冒泡拦截由该条件天然覆盖。焦点落入改 `focusRowAfterLayout`（等 layout 完成后 requestFocus；`post{}` 早于 traversal 会静默漏焦）。节目单呼出后应可直接上下浏览行=验收点。
- 底部 nowBar（当前节目条，6s 自动隐藏）不属于控制条，保留。

## ④ 订阅管理界面改版（SubsActivity + activity_subs.xml）

**双栏分块布局**（草图 A 分块版，已定稿）：

- **顶栏**：标题「订阅管理」＋右上角「＋ 添加订阅」（走现有添加流程）。
- **左列＝订阅卡片列表**：每张卡两行——订阅名（大字）＋ meta 小字「N 台 · 刷新时间」，右侧状态徽标（绿「当前」/灰「未启用」）；卡片间明显间距（解决"中间留空太大/太紧凑"两头的反馈）；选中卡高亮描边；超屏滚动。
- **右列＝详情＋操作**：选中订阅的名称/URL/台数，竖排按钮 **设为当前 / 刷新订阅 / 编辑 / 删除**。
- **焦点流**：LEFT/RIGHT 两栏互切，UP/DOWN 栏内移动（框架默认）。
- **⑥（原批次第 6 条「选中订阅直接刷新/启用」）由本布局天然覆盖**：操作对象＝左列当前焦点订阅，右键进按钮列即点即用。
- **新增数据**：`Subscription` 加列 `lastUpdatedAt: Long = 0`（Room 版本+1、迁移加列），**凡拉取全量频道成功即写入**——手动「刷新订阅」、SubEditActivity 新增保存、编辑保存三处都写（否则新添加的订阅会立刻显示「未刷新」，反直觉）；卡片 meta 显示之（0 → 「未刷新」）。台数＝按 `subscriptionId` count。
- 按钮语义沿用现有：设为当前=现 btnCurrent、刷新=现 btnRefresh（对**焦点订阅**执行，不再依赖"先选中再点底部"）、编辑/删除同理。

## ⑤ 设置页（新 SettingsActivity）

- **入口**：首页顶栏「全部/收藏/订阅管理/多屏观看」后追加「设置」tab。
- **条目**（TV 竖排列表，焦点行＋确认交互）：
  1. **频道显示方式**：列表 / 画廊 —— 确认键在两值间切换，行上直接显示当前值。
  2. **画廊一行几路**：2/3/4/5 —— 确认键循环切换，默认 3。
  3. **关于版本**：显示 `versionName (versionCode)`，纯展示不可点（读 `packageManager.getPackageInfo`，不依赖 BuildConfig 开关）。
- **持久化**：`SharedPreferences`（如 `"ui_settings"`）：`display_mode`（`"list"|"grid"`，默认 `"list"`）、`grid_span`（Int，默认 3，读时 coerce 2..5）。存取与循环切换抽成**纯逻辑函数**（零 Android 依赖）以便 JVM 测试。
- **生效**：从设置页返回首页后立即按新模式渲染（实现方式：`onResume` 重读设置并重设 layoutManager/adapter）。

## 目标 / 非目标 / 反目标

- **目标**：五项全部落地且旧功能零回归（40/40 测试保持绿）；TV 遥控器纯按键可达所有新交互。
- **硬性验收步骤（真机，用户执行）**：Room 加列迁移 JVM 测不到（不加 Robolectric/androidTest 依赖）——验收必须包含「装 v1.1 且已有订阅+收藏数据的电视 → **覆盖安装**本批次包 → 订阅与收藏完好」，不得只测全新安装。
- **非目标**：回看；画廊实时画面预览；多屏页任何改动；改设置页条目以外的新开关；升版本号。
- **反目标**：为了"可配置"把简单界面做成选项迷宫——设置页只有上面三行，不加第四行。

## 我的裁决清单（用户未指定，我定，可复议）

1. 绿色取 `#4CAF50`，且只绿「网络~xxms」片段（SpannableString，防复用传染）。
2. 画廊占位＝无台标时灰底图标（不做首字母色块）。
3. 画廊仅作用于「全部」tab；收藏 tab 保持列表（不为收藏发明新行为）。
4. 播放页左键不做任何事；nowBar 保留。
5. 面板互斥（节目单/频道列表不同时开）。
6. 播放页抽屉隐藏订阅 chips（`showSubChips` 参数），换台恒在当前订阅。
7. `lastUpdatedAt` 三处写入（手动刷新/新增/编辑保存），历史订阅显示「未刷新」。
8. 设置持久化用 SharedPreferences 而非 Room。
9. 首页「设置」tab 与现有 tabs 同样式，放最后。

以上 1-9 中第 3、6 条是对早期对话口径的收紧修正（此前说过「收藏列表同步切换」「零改造复用」），理由如上；用户可复议。

## 留给实施者的点

- ChannelDrawer 的标题文案（多屏是「选择频道·第N格」）在播放页场景下取什么——建议「选择频道」。
- Room 迁移写法（手写 `@Migration` 加列 vs `fallbackToDestructiveMigration`——用户数据含订阅 URL 与收藏，**不得破坏性重建**，须手写迁移）。
- 设置页与首页间的具体刷新机制（recreate vs 手动 apply）不限定，行为标准＝返回首页立即正确。
